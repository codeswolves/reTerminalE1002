# 任务推进流程跟踪树状图 — 设计文档

## 1. 目标

基于 `data/task_flows.json` 中的任务数据，构建**任务流程跟踪树**，实现：

- 可视化每个任务从创建到完成（或当前状态）的全流程节点
- 每个节点标注**负责人**、**时间戳**、**距上一节点耗时**
- 汇总任务全流程**总耗时**
- 便于事后复盘，识别瓶颈与阻塞环节
- 支持通过 Web 界面交互式增删改节点

## 2. 数据源

`data/task_flows.json` — 唯一数据源（JSON 格式），每个任务条目结构如下：

```json
{
  "no": "1",
  "name": "完成进度看板项目",
  "date": "2026/08/01",
  "priority": "high",
  "category": "工程",
  "nodes": [
    {"phase": "创建", "date": "2026/08/01", "progress": 70, "note": ""},
    {"phase": "推进", "date": "2026/08/01", "progress": 100, "note": "", "owner": "张三"}
  ]
}
```

| 字段 | 含义 | 说明 |
|------|------|------|
| no | 任务编号 | 字符串，自增 |
| name | 任务名称 | — |
| date | 创建日期 | 格式 YYYY/MM/DD |
| priority | 优先级 | high / medium / low |
| category | 任务分类 | 科研 / 工程 / 个人 / 标准 / 专利 |
| nodes | 流程节点列表 | 按时间顺序排列 |

**节点（node）字段：**

| 字段 | 含义 | 必填 |
|------|------|------|
| phase | 阶段名称 | 是（创建/推进/当前/完成） |
| date | 节点日期 | 是 |
| progress | 进度(%) | 是 |
| note | 备注 | 否 |
| owner | 负责人 | 否 |

**派生字段**（由 `read_tasks()` 在读取时计算，不存储在 JSON 中）：

- `finished`：最后节点 progress>=100 且 phase 为"完成"或"推进" → True
- `status`：已完成 / 进行中 / 未开始
- `total_days`：已完成 = 完成日期 - 创建日期；进行中 = 今天 - 创建日期
- `stalled`：创建超 7 天且进度为 0 → 疑似停滞
- `days_from_prev`：每个节点距上一节点的天数差

## 3. 树状图结构设计

每个任务独立生成一棵流程树，所有任务按**分类（category）** 分组展示。

### 3.1 单任务流程树示例

**已完成任务：**

```
● 完成进度看板项目  ✅
│
├── [创建] 2026/08/01  进度: 70%
│
├── [推进] 2026/08/01  进度: 100%  ⏱ 距上节点: 0天
│
└── 📊 全流程总耗时: 0天
```

**进行中任务：**

```
● 完成网络测量标准提纲  ⏳
│
├── [创建] 2026/08/01  进度: 26%
│
├── [当前] 2026/08/31  进度: 26%  ⏱ 距创建: 30天
│   ⚠️ 疑似停滞
│
└── 📊 已耗时: 30天（进行中）
```

### 3.2 页面整体结构

页面按分类分组，每组内以卡片列表展示该分类下的任务流程树。
页面顶部有统计概览（动态 JS 计算）和筛选/排序按钮。

### 3.3 状态标识

| 状态 | 标识 | 判定规则 |
|------|------|----------|
| 未开始 | ○ | progress = 0 且未完成 |
| 进行中 | ⏳ | progress > 0 且未完成 |
| 已完成 | ✅ | 最后节点 progress >= 100 |
| 已暂停 | ⏸️ | 手动标记 |
| 已取消 | ❌ | 手动标记 |

## 4. 架构与交互

### 4.1 技术架构

- **数据层**：`data/task_flows.json`（单一 JSON 文件）
- **生成层**：`src/generators/generate_task_flow.py` — 读取 JSON，生成静态 HTML（含嵌入数据，支持 file:// 模式）
- **服务层**：`src/utils/serve_task_flow.py` — 本地 HTTP 服务器，提供静态文件服务 + REST API
- **页面**：`output/tasks/task_flow.html` — 优先从 API 加载数据，API 不可用时回退到嵌入数据

### 4.2 REST API 接口

服务器提供以下 API：

| 接口 | 方法 | 功能 |
|------|------|------|
| `/api/tasks` | GET | 获取所有任务（含计算字段） |
| `/api/add_node` | POST | 为任务添加流程节点 |
| `/api/edit_node` | POST | 编辑指定节点 |
| `/api/delete_node` | POST | 删除指定节点 |
| `/api/add_task` | POST | 添加新任务 |
| `/api/delete_task` | POST | 删除任务 |
| `/api/complete_task` | POST | 一键完成任务 |

### 4.3 交互功能

- **按分类筛选**：全部 / 科研 / 工程 / 标准 / 专利 / 个人
- **按状态筛选**：全部 / 未完成 / 未开始 / 进行中 / 已完成 / 已暂停 / 已取消
- **按优先级排序**：high → medium → low
- **按耗时排序**：升序/降序
- **按创建时间排序**
- **展开/折叠分类组**
- **添加/编辑/删除节点**（弹窗表单）
- **一键完成任务**（✅ 按钮）
- **跨页面导航**：tasks_view → task_flow（?task=No. 参数自动定位高亮）

### 4.4 统计动态计算

两个页面（`tasks_view.html` 和 `task_flow.html`）的统计数字均由 JavaScript 从 API 数据实时计算，不再在 Python 生成时写死。数据加载后调用 `updateStats()` 函数更新所有计数元素。

## 5. 耗时计算规则

| 场景 | 计算方式 |
|------|----------|
| 已完成任务 | `completed_date - create_date` |
| 进行中任务 | `today - create_date` |
| 无推进记录 | 标记为 ⚠️ 疑似停滞（创建超 7 天且进度为 0） |

## 6. 复盘分析维度

页面底部复盘区域包含：

- **按分类统计**：各分类的任务数、完成率、平均耗时
- **超期任务 TOP5**：已完成任务中耗时最长的
- **停滞任务**：进行中但长期无进度更新的
- **优先级倒挂**：low 优先级已完成但 high 优先级未完成的

## 7. 文件清单

| 文件 | 用途 |
|------|------|
| `data/task_flows.json` | 唯一数据源（任务元数据 + 流程节点） |
| `src/generators/generate_task_flow.py` | 任务流程跟踪树页面生成脚本（含数据层 read_tasks/read_tasks_raw/write_tasks_raw） |
| `src/generators/generate_tasks_view.py` | 任务总览页面生成脚本（复用 generate_task_flow 的数据层） |
| `src/utils/serve_task_flow.py` | 本地 HTTP 服务器（静态文件 + REST API） |
| `output/tasks_view.html` | 任务总览页面（入口页） |
| `output/task_flow.html` | 任务流程跟踪树页面 |
